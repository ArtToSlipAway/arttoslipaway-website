# Приватные вложения и безопасное внедрение

Публичные работы (`app/uploads`) и вложения заявок (`private_files`) хранятся
отдельно. Приватный каталог не подключается через StaticFiles или Nginx alias.
Проверка доступа выполняется при каждом скачивании; случайное имя файла само
по себе не считается авторизацией. Старые, внешние пути и symlinks отклоняются.

## Клиентские ссылки

Клиентская ссылка — bearer credential. Получивший её может открыть заявку.
Не публикуйте её в GitHub, аналитике, журналах и скриншотах.
Uvicorn запускается с `--no-access-log`; Nginx не пишет access log для `/client/`.
Настройте аналогичные исключения в CDN, мониторинге и error tracking.
Клиентские страницы используют `no-store` и `Referrer-Policy: no-referrer`.
Административные HTML-формы используют `same-origin`: политика `no-referrer`
может заставить браузер отправить `Origin: null`, что мешает CSRF-проверке.

## Переход со старой версии

Простое обновление кода не убирает ранее загруженные файлы из публичной папки.
Новые обработчики не открывают старые пути, но их прежние URL могут продолжать
работать через Nginx/StaticFiles, пока файлы остаются в `/uploads`.

1. Сделайте защищённую резервную копию приложения, БД и файлов.
2. На отдельной копии сопоставьте записи `lead_files` с файлами. Проверьте,
   не используются ли те же файлы как публичные работы.
3. Приостановите загрузки на время переноса. Скопируйте вложения в `private_files`
   с новыми случайными именами, проверьте размер и контрольные суммы.
4. Транзакционно обновите только соответствующие строки `lead_files`. Сохраните
   защищённую таблицу старых и новых путей для отката.
5. Уберите оригиналы вложений из публичных папок в защищённую резервную копию;
   учтите кеши CDN/proxy. Не удаляйте общие файлы каталога без проверки.
6. Убедитесь, что старый URL не работает, своё вложение доступно, а чужое,
   просроченное и отозванное — нет. Проверьте отсутствие токенов в логах.
7. После проверок возобновите приём заявок.

Перенос реальных данных автоматически не выполняется. Для production нужны
HTTPS, `ADMIN_COOKIE_SECURE=true`, точный список доменов в
`ADMIN_CSRF_ALLOWED_ORIGINS` и права записи приложения в оба каталога файлов.
Nginx не должен иметь публичного маршрута к `private_files`.

## Границы проверки

Тесты проверяют основные сценарии входа и доступа к вложениям. Они не являются
пентестом и не проверяют антивирусную защиту, дисковые квоты, все административные
операции или нагрузку. Примеры Nginx/systemd необходимо проверить (`nginx -t`)
и адаптировать на staging. Рабочий сервер в этой задаче не обновлялся.
